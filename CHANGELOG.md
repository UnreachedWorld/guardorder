## 0.1.0 — 2026-11-12

The check carried from the reviewed tree at 4eb5f6802.

A founder admission is a new INSERT. The checker looks for the check in the
project GuardOrder was built for, self._founder(, before that. UPDATE and DELETE
changes are not covered. An insert through executemany, executescript, a cursor, a with self.db, a later
insert in the same script, an f-string, or a local name saved from self.db is
still that admission. The verb is read from that call's own string. SQL with no visible verb gets
a card. A cursor from a renamed database, only the first with-name, and a
comment before the verb stay limits. A differently named
check is matched as written.

First review package.

The check is read-only. You name a guard and an action. A card gives the file
and the line of the action. A quiet result is not proof the code is safe.

A comment, a quote, a function definition, and a bare `//` comment are not the
guard or the action. `x = foo() // other()` stays, because that is division.
A begin or a select inside `execute` is not the public effect. Another receiver
counts only when the rule names it.

The package notes use the same run line as the root notes. The tools-folder
path is the engine layout and is not in this tree.
